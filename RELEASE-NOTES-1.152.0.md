# pinn. 1.152.0

**Your own reverse proxy instead of Tailscale**

- **Access from the internet without a VPN app.** Put pinn. behind your own reverse proxy (Nginx Proxy Manager, Traefik, Cloudflare Tunnel …) that forwards to `http://<NAS-IP>:8090`. Step-by-step guide in the README under “Access from the internet with your own reverse proxy”.
- **Real visitor address.** pinn. now only believes the address a proxy passes on (`X-Forwarded-For`) if the request really comes from a trusted proxy – by default the home network, Docker networks and Tailscale. Other setups (a rented server, Cloudflare's orange cloud in front of your proxy) are set with `PINN_PROXY_NETZE`, e.g. `privat, cloudflare`. So the lock after many wrong passwords can no longer be dodged with faked addresses; with IPv6 the whole /64 network counts.
- **Protection from the internet.** The PocketBase administration (`/_/`), the PocketBase admin interfaces and PocketBase's own sign-in ways answer only in the home network. The start password `Admin` does not work from outside. Whoever sends many unknown device IDs to the location service is ignored for an hour (entry in the error log).
- **Security warnings to the admins.** In addition to the lock, the admins get a push “🚨 Security warning” whenever someone tries to get around a protection or to guess something: many wrong passwords (per address or per profile), wrong PINs on a family dashboard, the start password from the internet, access to the PocketBase administration, unknown tracker IDs, invalid access keys (dashboard, widget, smart home). The push names the address, home network or internet, and the device; the error log (new area “Security”, opened by tapping the push) has everything that is known: IPv4/IPv6 and /64 network, proxy and `X-Forwarded-For`, browser identifier, device name from the app, language, Origin/Referer, request, targeted family/profile/dashboard, number of attempts and a link to look the address up yourself. Nothing is sent to other services. Family matters go to that family's admins and the main admin, matters of the whole server to all admins – without family or profile names. At most one push per hour and address, at most 20 per hour on the server.
- Nothing changes in the home network and via Tailscale/WireGuard. Existing installations need no action.

# pinn. 1.152.0 (Deutsch)

**Eigener Reverse Proxy statt Tailscale**

- **Zugriff aus dem Internet ohne VPN-App.** pinn. hinter einen eigenen Reverse Proxy stellen (Nginx Proxy Manager, Traefik, Cloudflare Tunnel …), der an `http://<NAS-IP>:8090` weiterleitet. Schritt-für-Schritt-Anleitung in der README unter „Zugriff aus dem Internet mit eigenem Reverse Proxy“.
- **Echte Besucher-Adresse.** pinn. glaubt die von einem Proxy weitergereichte Adresse (`X-Forwarded-For`) nur noch, wenn die Anfrage wirklich von einem vertrauten Proxy kommt – standardmäßig Heimnetz, Docker-Netze und Tailscale. Andere Aufbauten (gemieteter Server, Cloudflares orange Wolke vor dem eigenen Proxy) stellt man mit `PINN_PROXY_NETZE` ein, z. B. `privat, cloudflare`. So lässt sich die Sperre nach vielen falschen Passwörtern nicht mehr mit gefälschten Adressen umgehen; bei IPv6 zählt das ganze /64-Netz.
- **Schutz aus dem Internet.** Die PocketBase-Verwaltung (`/_/`), die PocketBase-Verwaltungsschnittstellen und PocketBases eigene Anmeldewege antworten nur im Heimnetz. Das Start-Passwort `Admin` funktioniert von außen nicht. Wer viele unbekannte Geräte-IDs an die Ortung schickt, wird eine Stunde lang ignoriert (Eintrag im Fehlerprotokoll).
- **Sicherheitswarnungen an die Admins.** Zusätzlich zur Sperre bekommen die Admins eine Push-Mitteilung „🚨 Sicherheitswarnung“, wenn jemand versucht, einen Schutz zu umgehen oder etwas zu erraten: viele falsche Passwörter (je Adresse oder je Profil), falsche PINs am Familien-Dashboard, das Start-Passwort aus dem Internet, Zugriffe auf die PocketBase-Verwaltung, fremde Tracker-IDs, ungültige Zugangsschlüssel (Dashboard, Widget, Smart Home). Die Mitteilung nennt Adresse, Heimnetz oder Internet und Gerät; im Fehlerprotokoll (neuer Bereich „Sicherheit“, öffnet sich beim Tippen auf die Mitteilung) steht alles, was bekannt ist: IPv4/IPv6 und /64-Netz, Proxy und `X-Forwarded-For`, Browser-Kennung, Gerätename aus der App, Sprache, Origin/Referer, Anfrage, betroffene Familie/Profil/Dashboard, Anzahl der Versuche und ein Link, um die Adresse selbst nachzuschlagen. Nichts wird an andere Dienste geschickt. Familien-Sachen gehen an die Admins der Familie und den Hauptadmin, Server-Sachen an alle Admins – ohne Familien- und Profilnamen. Höchstens eine Mitteilung pro Stunde und Adresse, höchstens 20 pro Stunde auf dem Server.
- Im Heimnetz und über Tailscale/WireGuard ändert sich nichts. Bestehende Installationen müssen nichts tun.
